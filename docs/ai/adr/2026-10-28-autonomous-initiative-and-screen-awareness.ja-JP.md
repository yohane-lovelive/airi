# 自律的な発話(Initiative)と画面認識

ステータス: proposed

英語版: [2026-10-28-autonomous-initiative-and-screen-awareness.md](./2026-10-28-autonomous-initiative-and-screen-awareness.md)

> この文書は英語版 ADR の日本語訳です。内容が食い違う場合は英語版が正です。

## 背景

AIRI が話すのは、オーナーのメッセージかモジュールのイベントを受けたときだけです。Neuro-sama のように、キャラクターから会話を始めることはできません。

キャラクターは、オーナーが PC で何をしているかも知りません。画面のパイプラインは既にありますが、次の不足があります。

- 画面ティッカーを起動できるのは `devtools/vision.vue` だけです。オーナーはそのページを開いたままにして、キャプチャ元を手動で選ぶ必要があります。
- ティッカーは 3 秒ごとに視覚モデルを呼びます。画面が変わらなくても呼びます。
- `publishContext` は既定でオフです。
- コンテキストがモデルに届くのは、次のオーナーのメッセージと一緒のときだけです。画面が変わってもターンは始まりません。
- パイプラインには除外ルールがなく、ロック画面で止まることもありません。

次の既存部品を、この変更で再利用します。

- `packages/stage-ui/src/stores/chat.ts` の `notifyConversation` は、オーナーの会話に通知(notice)を送ります。モデルは話すか、黙るかを選びます。黙った通知は履歴に残りません。
- レンダラーのリーダーがバックグラウンド処理を実行します。複数のウィンドウが同じ処理を重複して行うことはありません。
- サスペンドとロック画面の `powerMonitor` イベントは、Eventa 経由でレンダラーに届きます。
- ビジョンストア、オーケストレーター、`sendContextUpdate` が、画面の説明を生成して配信します。

[ADR 2026-10-10](./2026-10-10-skills-automations-and-memory.md) は、トリガー、条件、クールダウンを持つ自動実行レシピを定義しています。`main` のコードには、まだ automation がありません。

## 決定

AIRI に、連携して動く 2 つの機能を追加します。画面認識は、キャラクターに画面のコンテキストを与えます。Initiative は、キャラクターがターンを開始できるようにします。
どちらの機能も既定はオフで、`apps/stage-tamagotchi` のみが対象です。

### Initiative

- トリガーは、ターンを開始できるイベントです。一定時間の沈黙、大きな画面変化、離席後の復帰、ゆらぎ付きのタイマーがあります。
- 各トリガーと各ゲートは、モデルを呼ばずにコードが判断します。
- ゲートは、オーナーが入力中または発話中のとき、キャラクターが発話中のとき、ターンが実行中のときに、ターンを止めます。
- ゲートは、静音時間、クールダウン中、1 日の予算を使い切ったときにも、ターンを止めます。
- Initiative のターンにオーナーが反応しなかった場合、クールダウンは長くなります。オーナーが反応すると、基本値に戻ります。
- トリガーがすべてのゲートを通過すると、ホストは `initiative:<trigger>` をソースにして `notifyConversation` を呼びます。
- 通知のテキストには、トリガー名と経過時間を入れます。直近の Initiative の発話も入れて、モデルが同じことを繰り返さないようにします。
- 話すか黙るかは、モデルが決めます。コードが返答を偽装することはありません。
- オーナーは、基本間隔、静音時間、1 日の予算を設定します。既定の間隔は控えめで、静かな時間が 5〜10 分続いたら 1 ターンです。
- `spark:notify` によるモジュールイベントは、従来の経路のままです。これらのゲートは使いません。

### 画面認識

- ウォッチャーはレンダラーのリーダーで動きます。devtools ページには依存しません。オーナーは設定でキャプチャ元を一度選び、アプリがそれを保持します。
- ウォッチャーは各フレームを縮小し、直前のフレームと比較します。差が閾値を超えたときだけ、視覚モデルを呼びます。
- 画面が静止している間は、ウォッチャーは間隔を延ばします。画面が変化している間は、間隔を縮めます。間隔の両端には上限と下限があります。
- ウォッチャーは、短いテキストの説明を、コンテキスト `screen:activity` として `ReplaceSelf` で配信します。画像は既定では添付しません。
- ダイジェストは、直近の説明を少数だけメモリに保持します。ダイジェストがディスクに書き込まれることはありません。
- ダイジェストで大きな変化があれば、それが Initiative の `screen-change` トリガーになります。

### プライバシー

視覚モデルはクラウドモデルです。フレームが PC の外に出るため、初回リリースから次のルールを必須にします。

- 画面認識はオプトインです。設定画面に、画面の内容が選択したクラウドプロバイダーに送られることを明記します。
- ウォッチャーの動作中は、インジケーターを表示します。1 クリックで一時停止できます。
- 除外リストに、アプリとウィンドウタイトルを指定します。一致したフレームはスキップします。既定のリストには、パスワードマネージャー、銀行、メッセンジャーを含めます。
- ウォッチャーは、サスペンド時、ロック画面時、キャプチャ元が消えたときに一時停止します。
- アプリはフレームを保存しません。保持するのは、メモリ上のテキストの説明だけです。

### 設定とコスト

- オーナーは、キャプチャ間隔の範囲、変化の閾値、1 日の視覚モデル呼び出しの予算を設定します。この予算はコストの上限にもなります。
- Initiative と画面認識には、それぞれスイッチがあります。画面認識がなくても、沈黙とタイマーのトリガーだけで Initiative は動きます。

## 実装の境界

- `packages/core-agent` が、移植可能なポリシー(トリガー、ゲート、バックオフ、予算)を持ちます。これらは時計を入力に取る純粋関数です。
- `packages/stage-shared` が、フレームの比較を持ちます。Vue への依存はありません。
- `packages/stage-ui` が、ストア、ウォッチャーのループ、`notifyConversation` とビジョンオーケストレーターへの接続を持ちます。
- `apps/stage-tamagotchi/src/main` が、アイドル時間と、除外ルール用のウィンドウ一覧を持ちます。
- これらの呼び出しの Eventa コントラクトは、`apps/stage-tamagotchi/src/shared` に置きます。
- 文字列は `packages/i18n` に置きます。変更するのは、英語ロケールと作成者のロケールだけです。
- 両方の機能は、レンダラーのリーダーが実行します。他のウィンドウは状態を読むだけです。

## automation との関係

`trigger`、`condition`、`cooldown` という名前は、ADR 2026-10-10 に合わせます。automation のコードが `main` にないため、Initiative は独立したモジュールとして先に出荷します。
automation が入ったら、Initiative はプリセットの automation になり、ゲートは条件になります。そのときは、この ADR を更新します。

## 検証

- 偽の時計を使った決定的テストで、各トリガー、各ゲート、バックオフ、予算を検証します。
- フレーム比較のテストで、静止フレーム、小さな変化、大きな変化を検証します。
- ストアのテストで、ゲートが止めたときに `notifyConversation` が呼ばれないことを確認します。
- ブラウザテストで、設定ページとインジケーターを検証します。
- 実際のクラウドモデルと実際の画面を使ったライブ確認は、CI の対象外です。結果は PR に記録します。

## 非ゴール

- ローカルの視覚モデル。初回リリースが対応するのは、クラウドプロバイダーのみです。
- `stage-web` と `apps/stage-tamagotchi-kirie` での画面認識。
- 画面の内容に基づく PC の操作。コンピューター操作は、専用のツールが担当します。
- フレームの保存と、長期の画面履歴の保存。
