# 自律のアイデアメモ

英語版: [autonomy-ideas.md](./autonomy-ideas.md)

> この文書は英語版の日本語訳です。内容が食い違う場合は英語版が正です。

このファイルは、オーナーが後に回した機能を保持します。これらは[自律の ADR](../adr/2026-10-28-autonomous-character-perception-and-missions.ja-JP.md) の範囲外です。
各項目は、機能の内容、待つ理由、もう一度検討するときを示します。項目の作業を始める前に、専用の設計か ADR の変更が必要です。

ADR の「既知のリスク」の表も、3 つの項目を保持します。自分の声を拾う問題、画面からのプロンプトインジェクション、通話中の発話です。

## 会話と在席

### 通話中・会議中のおやすみモード

- **内容:** 他のアプリがマイクを使っているとき、動画が全画面で再生されているとき、録画ソフトが動いているときに、キャラクターが静かになります。
- **待つ理由:** オーナーは Discord の通話で AIRI を使う予定です。固定のミュートのルールは、その使い方を妨げます。
- **もう一度検討するとき:** Discord の音声通話への参加に設計ができたとき。このルールは、AIRI が通話に参加しているかを知る必要があります。

### Discord の音声通話への参加

- **内容:** AIRI が Discord の音声通話に入り、オーナーや友人と話します。ボットは話者ごとに 1 つの音声ストリームを受け取るため、誰が話したかが分かります。
- **待つ理由:** 今の用途は、個人用のデスクトップエージェントです。AIRI の Discord モジュールは、テキストだけを扱います。
- **もう一度検討するとき:** 自律のステップ 0〜3 が動いたとき。将来の ADR が必要です。

### 配信の視聴者への反応

- **内容:** キャラクターが、Twitch や YouTube の視聴者のチャットを読んで答えます。
- **待つ理由:** 今の用途は、配信ではなく個人用です。
- **もう一度検討するとき:** オーナーが AIRI と一緒に配信を始めたとき。

### サーバー側でのターンの実行

- **内容:** サーバーが、記憶の検索、モデルの呼び出し、ツールを含むターン全体を実行します。各端末は結果を再生するだけです。
- **待つ理由:** 今の設計は、モデルの呼び出しを各端末に残し、サーバーは記憶の検索だけを担当します。全体を移すと、AIRI の構造が変わります。
- **もう一度検討するとき:** 記憶の ADR が動いていて、端末ごとに結果や設定がずれるとき。

## 費用

### 用途ごとの 1 日の費用の上限

- **内容:** 呼び出しの用途ごとに、1 日の費用の上限を設けます。上限に達した用途は止まります。
- **待つ理由:** オーナーは、まず使用量を見たいと考えています。ADR は用途ごとの使用量を表示します。
- **もう一度検討するとき:** 使用量の表示で、想定より費用のかかる用途が見つかったとき。

## 知覚

### 見慣れた画面の判定に画像の埋め込みを使う

- **内容:** EmbeddingGemma 2 は、画像とテキストを 1 つのベクトル空間に置きます。画像の埋め込みは、小さなハッシュより上手に見慣れた画面を見つけられます。
- **待つ理由:** ハッシュのほうが安く、改善の幅をまだ誰も測っていません。
- **もう一度検討するとき:** リプレイ評価で、メニューや繰り返し出る画面がまだターンを起こしているとき。

### ローカルの視覚モデル

- **内容:** ローカルのモデルがフレームを読むため、フレームが PC の外に出ません。
- **待つ理由:** 初回リリースはクラウドプロバイダーだけに対応します。品質のよいローカルモデルには、強い GPU が必要です。
- **もう一度検討するとき:** 画像入力のある小さなローカルモデルが、リプレイ評価でよい実況をしたとき。

### リアルタイム・ストリーミング API

- **内容:** Gemini Live のようなモデルが、音声と映像をストリームで受け取り、音声で答えます。
- **待つ理由:** この設計は、判断ターンとテキストのモデルを使います。リアルタイムのモデルは、発話の経路と費用の仕組みを変えます。
- **もう一度検討するとき:** 割り込みとフレームポリシーを使っても、判断ターンの遅延が実況には大きすぎるとき。

### ほかの端末での画面の知覚

- **内容:** `apps/stage-pocket` や `apps/stage-tamagotchi-kirie` での画面の知覚。
- **待つ理由:** オーナーは、スマホで画面の知覚を必要としません。
- **もう一度検討するとき:** オーナーが PC でこれらのアプリを使うとき。

### ほかのプラットフォームでのゲームの音声

- **内容:** macOS や Linux でのプロセス単位の音声キャプチャ、または web 版でのゲームの音声。
- **待つ理由:** オーナーがゲームの音声を必要とするのは、Windows のデスクトップ版だけです。
- **もう一度検討するとき:** オーナーが別のプラットフォームでゲームをするとき。

## モーション

### リップシンク

- **内容:** TTS の発話に合わせた口の動き。コードには `useVRMLipSync` がありますが、まだ誰も検証していません。
- **待つ理由:** オーナーが要件を一旦取り下げました。
- **もう一度検討するとき:** ステップ 4 のモーションの層が動いたとき。

### 音声から身振りを作るモデル

- **内容:** 小さなニューラルモデルが、発話の音声を上半身のモーションに変えます。例は、DiffGesture や Audio2Photoreal の系統のモデルです。
- **待つ理由:** 手続き生成の層とクリップのライブラリが先で、これらはモデルを必要としません。
- **もう一度検討するとき:** ライブラリの身振りが、繰り返しに見えすぎるとき。

### モデルによるモーションの制御

- **内容:** モデルが、クリップの名前ではなく、視線の目標、頭の角度、ポーズの混ぜ具合を指定します。
- **待つ理由:** 自由文マーカーとクリップのほうが単純で、品質が安定します。
- **もう一度検討するとき:** ライブラリでは小さな反応を表せないとき。例は、画面の一部をちらっと見る動きです。
